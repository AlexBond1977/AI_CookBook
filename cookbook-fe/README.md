# 🍳 CookBook — Frontend

Учебное frontend-приложение для поиска и просмотра рецептов. Работает с
готовым backend API (`cookbook-be`), поддерживает поиск, фильтрацию по
категориям, избранное и историю просмотров.

> **Учебный проект.** Создан в рамках домашнего задания при помощи ИИ.
> Не предназначен для production-использования.

---

## ✨ Возможности

- **Список рецептов** — все блюда с обложкой, категорией и временем приготовления.
- **Поиск по названию** — мгновенная фильтрация списка с дебаунсом 300 мс.
- **Фильтр по категории** — Italian, Asian, Mexican и другие.
- **Избранное** — добавление и удаление рецептов в один клик, с оптимистичным
  обновлением интерфейса и откатом при ошибке.
- **История просмотров** — блок Recently Viewed автоматически обновляется
  после открытия рецепта.
- **Страница рецепта** — обложка, ингредиенты, пошаговая инструкция,
  управление избранным.
- **Адаптивная вёрстка** — 3 карточки в ряд на десктопе, 2 на планшете,
  1 на мобильных.
- **Понятные состояния** — спиннер при загрузке, «Не удалось загрузить» с
  кнопкой Retry при ошибке, дружелюбные плейсхолдеры для пустых списков.

## 🧱 Стек

Без сборщика и без фреймворков — только нативные веб-технологии:

- **HTML5** — семантическая разметка, один `index.html`.
- **CSS3** — обычный CSS с дизайн-токенами на CSS-переменных и медиа-запросами.
- **JavaScript (ES-модули)** — `<script type="module">`, нативные `import`/`export`,
  без npm-зависимостей на клиенте.

Взаимодействие с backend — через `fetch`, все HTTP-запросы инкапсулированы
в одном модуле `src/api.js`.

## 📁 Структура проекта

```
cookbook-fe/
├── index.html          # Разметка приложения: два экрана (главная и рецепт)
├── favicon.svg         # Иконка приложения
├── styles.css          # Все стили: палитра, сетки, карточки, адаптив
├── README.md           # Этот файл
└── src/
    ├── config.js       # Настройки: URL API, дебаунс, лимиты
    ├── api.js          # Обёртка над fetch: 5 функций под 5 эндпоинтов
    ├── store.js        # Единый стор состояния: данные, загрузка, ошибки
    ├── main.js         # Точка входа: связывает стор и UI
    └── ui/
        ├── card.js     # Карточка рецепта (используется в 3 блоках)
        ├── home.js     # Главный экран: поиск, фильтр, три блока
        └── recipe.js   # Страница рецепта
```

### Архитектура в двух словах

Единый поток данных: **store → main.js → UI-модули**.

- `store.js` — единственный источник правды. Хранит рецепты, историю,
  фильтры, флаги загрузки и ошибок. Общается с API через `api.js`.
- `main.js` подписывается на изменения стора и перерисовывает экраны.
- UI-модули (`home.js`, `recipe.js`) не знают про store и API — получают
  состояние и колбэки через аргументы. Это делает их простыми и тестируемыми.

## 🚀 Запуск

### Требования

- Node.js 18+ (нужен для backend и для `npx serve`).
- Запущенный backend из соседней папки `cookbook-be` на `http://localhost:3001`.

### Шаг 1. Запустить backend

В отдельном терминале:

```bash
cd cookbook-be
npm install
npm start
```

Ожидаемый вывод: `CookBook backend is running on port 3001`.

### Шаг 2. Запустить frontend

В другом терминале:

```bash
cd cookbook-fe
npx serve
```

Ожидаемый вывод:

```
   ┌───────────────────────────────────────────┐
   │   Serving!                                │
   │   - Local:    http://localhost:3000       │
   └───────────────────────────────────────────┘
```

Откройте `http://localhost:3000` в браузере.

> **Почему `npx serve`, а не открытие `index.html` напрямую?**
> ES-модули (`<script type="module">`) не работают по протоколу `file://`.
> Нужен любой статический сервер — `serve` самый простой вариант.

## 🔌 Взаимодействие с API

Frontend использует 5 эндпоинтов backend'а. Все они собраны в `src/api.js`:

| Метод  | Путь                          | Назначение                          |
|--------|-------------------------------|-------------------------------------|
| `GET`  | `/recipes`                    | Список рецептов (карточки)          |
| `GET`  | `/recipes/:id`                | Детали рецепта                      |
| `PATCH`| `/recipes/:id/favorite`       | Обновление статуса избранного       |
| `POST` | `/recipes/:id/view`           | Отметка о просмотре                 |
| `GET`  | `/recipes/recently-viewed`    | Недавно просмотренные               |

Базовый URL API задаётся в `src/config.js`:

```js
export const API_BASE_URL = "http://localhost:3001";
```

Если backend запущен на другом порту — поменяйте значение здесь, и всё
приложение автоматически переключится.

### Замечание о `isFavorite`

Эндпоинт `GET /recipes/:id` **не возвращает** поле `isFavorite`. Поэтому на
странице рецепта состояние избранного берётся не из ответа этого эндпоинта,
а из общего списка `recipes` в сторе (он загружается один раз и уже
содержит `isFavorite` для каждого рецепта).

## 🎨 Дизайн

Тёплая «кухонная» палитра, аккуратные карточки со скруглениями и мягкими
тенями, адаптивная сетка:

- **Десктоп (> 900px)** — 3 карточки в ряд.
- **Планшет (560–900px)** — 2 карточки в ряд.
- **Мобильные (< 560px)** — 1 карточка в ряд, на всю ширину.

Цвета и размеры вынесены в CSS-переменные в `:root`, так что всю тему
можно поменять в одном месте файла `styles.css`.

## 🧪 Что можно проверить вручную

1. **Список** — открывается главная, видно 20 рецептов.
2. **Поиск** — введите `pasta`, в основном списке остаётся только Pasta Carbonara.
3. **Фильтр** — выберите `Italian`, в списке остаются 2 итальянских рецепта.
4. **Избранное** — клик по сердечку 🤍 на карточке: рецепт появляется в блоке
   Favorite Recipes. Повторный клик — пропадает.
5. **Просмотр** — откройте рецепт, вернитесь назад: он появился в блоке
   Recently Viewed.
6. **Ошибки** — остановите backend и обновите страницу: увидите заглушку
   «Failed to load» с кнопкой Retry. Запустите backend, нажмите Retry —
   всё загрузится.

## 📝 Заметки

- Backend хранит данные **в памяти**: избранное и история просмотров
  сбрасываются при перезапуске `cookbook-be`.
- Приложение рассчитано на **одного пользователя**.
- Роутинг — упрощённый: переключение экранов в состоянии, без изменения URL.
  Прямой переход на конкретный рецепт по ссылке невозможен.
- Обработка ошибок упрощённая: глобальная заглушка при загрузке и `alert`
  при ошибке мутации.
